# Есенин. Жизнь в стихах

Сайт музыкально-поэтического спектакля «Есенин. Жизнь в стихах» творческого объединения «Открытая Территория».

Описание постановки, участники, фотографии, публикации в СМИ и переход к покупке билетов собраны на одной странице.

**[Открыть сайт →](https://esenin-play.otkter.ru/)**

## Возможности

- Адаптивная верстка для мобильных устройств, планшетов и компьютеров.
- Информация о дате, времени и месте проведения спектакля.
- Переход к покупке билетов во внешнем билетном сервисе.
- Фотогалерея с полноэкранным модальным окном.
- Переключение фотографий стрелками и кнопками пагинации.
- Карточки участников постановки.
- Ссылки на публикации в СМИ и социальные сети.
- SEO-метаданные и структурированные данные события.

## Технологии

| Технология     | Назначение                                     |
| -------------- | ---------------------------------------------- |
| Astro 7        | Компоненты, маршрутизация и статическая сборка |
| TypeScript 6   | Типизация данных и клиентской логики           |
| Tailwind CSS 4 | Адаптивная верстка и стили                     |
| Astro Image    | Генерация оптимизированных изображений         |
| Astro Check    | Проверка Astro-компонентов и TypeScript        |
| Prettier       | Форматирование кода                            |
| GitHub Actions | Автоматическая сборка и публикация             |

Сайт генерируется в статический HTML. Для размещения production-сборки не требуется Node.js-сервер.

Интерактивность реализована на TypeScript через DOM API. React и другие клиентские UI-фреймворки не используются.

## Локальный запуск

Требования:

- Node.js версии 22.12.0 или выше;
- npm.

Клонируйте репозиторий и установите зависимости:

```bash
git clone https://github.com/khruartem/otkter-esenin.git
cd otkter-esenin
npm ci
```

Запустите сервер разработки:

```bash
npm run dev
```

По умолчанию сайт доступен по адресу [localhost:4321](http://localhost:4321/). Фактический адрес отображается в терминале.

| ---------------------- | --------------------------------------------- |

`npm run preview` использует уже созданную сборку. После изменения исходников предварительно выполните `npm run build`.

## Архитектура клиентской логики

Astro-компоненты формируют HTML при сборке. Клиентский TypeScript добавляет обработчики событий и обновляет интерфейс.

Основная точка сборки зависимостей — `src/scripts/index.ts`.

### Галерея

| Компонент                   | Ответственность                                                                               |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| `PhotoData`                 | Хранит фотографии и текущий индекс, проверяет выбор фотографии, обеспечивает переход по кругу |
| `GalleryController`         | Обрабатывает выбор фотографии в ленте                                                         |
| `PhotoPaginationController` | Обрабатывает выбор через пагинацию и обновляет активный элемент                               |
| `PhotoModalView`            | Клонирует HTML-шаблон, обновляет изображение и обрабатывает кнопки переключения               |
| `ModalController`           | Управляет открытием, закрытием и содержимым диалога                                           |
| `EventEmitter`              | Передает типизированные события между участниками                                             |
| `src/scripts/index.ts`      | Связывает пользовательские действия, модель и обновление интерфейса                           |

Контроллеры галереи и пагинации сообщают о действиях через события. Координатор изменяет модель и инициирует обновление представления.

Основные события:

| Событие                 | Данные                      |
| ----------------------- | --------------------------- |
| `gallery:photoSelected` | Индекс выбранной фотографии |
| `gallery:nextPhoto`     | Без данных                  |
| `gallery:previousPhoto` | Без данных                  |
| `gallery:photoChanged`  | Текущий индекс и фотография |

Типы данных связаны с названиями событий через `EventMap`. Метод `on()` возвращает функцию отписки.

Дополнительные контроллеры отвечают за поведение декоративной полосы при прокрутке и интерактивность карточек публикаций.

### Данные события

В `src/data/event.ts` объект `defaultData` передается в класс `PerformanceEvent`.

Дата начала хранится с часовым поясом:

```ts
startDate: "2026-10-06T19:00:00+03:00",
```

`dateLabel` задает видимую подпись даты отдельно. При изменении даты обновляйте оба значения.

Поддерживаемые статусы:

- `scheduled` — показ запланирован;
- `completed` — показ завершен;
- `cancelled` — показ отменен.

Статус задается вручную. Он не изменяется автоматически с течением времени.

Сведения о билетах:

```ts
tickets: {
  minPrice: 500,
  maxPrice: 1100,
  currency: "RUB",
  availability: "InStock",
},
```

При изменении цен или распродаже билетов обновляйте данные. Синхронизация с билетным сервисом не реализована.

Все изменения содержимого требуют новой сборки и публикации.

### Фотографии

Изображения галереи находятся в `src/assets/images/gallery/`.

В `src/data/photos.ts` каждая фотография содержит:

- `src` — адрес полного изображения для модального окна;
- `thumb` — метаданные изображения для генерации миниатюр Astro;
- `alt` — текстовое описание фотографии.

Миниатюры генерируются в WebP с несколькими размерами и загружаются с `loading="lazy"`.

Для добавления фотографии импортируйте файл и добавьте объект в массив `photos`. Количество элементов пагинации определяется количеством фотографий.

## SEO

Основной адрес сайта:

**https://esenin-play.otkter.ru/**

Домен задан в `astro.config.mjs`:

```js
site: "https://esenin-play.otkter.ru/",
output: "static",
trailingSlash: "always",
```

В `BaseLayout.astro` настроены:

- язык документа `ru`;
- title и description;
- canonical на основе `Astro.site` и пути страницы;
- Open Graph;
- Twitter Card;
- favicon и Apple Touch Icon.

Изображение для превью находится в `public/preview.webp`. При его замене проверяйте ссылки и размеры в метаданных.

### Структурированные данные

`src/components/seo/EventStructuredData.astro` формирует JSON-LD типа `TheaterEvent`:

- название и описание;
- URL страницы и изображение;
- дату начала;
- статус события;
- площадку и адрес;
- организатора и исполнителей;
- предложение билетов `Offer`.

Блок `offers` выводится при статусе `scheduled`. Он содержит билетную ссылку, минимальную цену, валюту и наличие билетов.

JSON-LD входит в готовый HTML и не требует выполнения клиентского JavaScript.

### Служебные файлы

- `public/robots.txt` — правила для поисковых роботов и ссылка на sitemap.
- `public/sitemap.xml` — карта сайта с главной страницей.
- `public/yandex_6187913eb05ee334.html` — подтверждение прав в Яндекс Вебмастере.

Карта сайта поддерживается вручную. При добавлении новых страниц обновляйте `sitemap.xml`.

После изменения SEO проверяйте опубликованный HTML и структурированные данные. Успешная валидация разметки не гарантирует индексацию или расширенное отображение в поиске.

## Сборка и деплой

Production-сборка создается командой:

```bash
npm run build
```

Результат находится в `dist/`.

Автоматическая публикация настроена через GitHub Actions в `.github/workflows/deploy-ftp.yml`.

При push в `main` workflow:

1. Получает исходники репозитория.
2. Устанавливает зависимости через `npm ci`.
3. Выполняет `npm run build`.
4. Передает содержимое `dist/` на хостинг по FTP.

Для работы нужны GitHub Actions Secrets:

| Secret         | Назначение        |
| -------------- | ----------------- |
| `FTP_SERVER`   | Адрес FTP-сервера |
| `FTP_USERNAME` | Имя пользователя  |
| `FTP_PASSWORD` | Пароль            |

Целевой каталог на хостинге:

```text
/esenin-play.otkter.ru/docs/
```

В текущем workflow включен `dangerous-clean-slate: true`: перед загрузкой содержимое целевого каталога удаляется. Учитывайте это при размещении файлов вручную и изменении пути деплоя.

Проверки `npm run check` и `npm run format:check` пока не входят в workflow и выполняются отдельно перед публикацией.
