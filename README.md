# «Есенин. Жизнь в стихах»

Лендинг поэтического спектакля «Есенин. Жизнь в стихах» творческого объединения «Открытая территория».

Проект создается как самостоятельный статический сайт с собственным визуальным языком, адаптивной версткой и минимальным количеством клиентского JavaScript.

> Статус: в разработке.

## О проекте

Сайт знакомит зрителей со спектаклем и объединяет основную информацию о постановке в одном месте. Архитектура проекта рассчитана на быструю загрузку, корректную индексацию поисковыми системами и удобную работу на мобильных и десктопных устройствах.

## Технологии

- [Astro](https://astro.build/) 7
- [Tailwind CSS](https://tailwindcss.com/) 4
- TypeScript
- Prettier
- Astro Check

Сайт собирается статически и не требует серверного рендеринга.

## Требования

- Node.js 22.12.0 или новее
- npm

## Локальный запуск

Клонируйте репозиторий:

```bash
git clone https://github.com/khruartem/otkter-esenin.git
cd otkter-esenin
```

Установите зависимости:

```bash
npm install
```

Запустите сервер разработки:

```bash
npm run dev
```

После запуска сайт будет доступен по адресу `http://localhost:4321`.

## Команды

| Команда                | Назначение                                    |
| ---------------------- | --------------------------------------------- |
| `npm run dev`          | Запустить локальный сервер разработки         |
| `npm run build`        | Собрать production-версию в каталоге `dist`   |
| `npm run preview`      | Локально запустить собранную версию           |
| `npm run check`        | Проверить Astro-компоненты и TypeScript       |
| `npm run format`       | Отформатировать файлы с помощью Prettier      |
| `npm run format:check` | Проверить форматирование без изменения файлов |

## Архитектура

Проект представляет собой одностраничный статический сайт. Для него используется простая архитектура по назначению без FSD и других слоев, рассчитанных на крупные приложения.

Целевое направление зависимостей:

```text
pages → layouts + sections → components/ui
                    ↓
           assets + styles + utils
```

- `pages` собирает готовую страницу и не содержит сложной разметки;
- `layouts` определяет каркас HTML-документа, метаданные и общие подключения;
- `sections` содержит самостоятельные смысловые блоки лендинга;
- `components/ui` содержит небольшие переиспользуемые элементы интерфейса;
- `assets`, `styles` и `utils` не зависят от компонентов верхнего уровня.

### Целевая структура

```text
/
├── .github/
│   └── workflows/             # CI и production-деплой
├── public/                    # Файлы, копируемые в сборку без обработки

│   ├── favicon.svg
│   ├── og-image.webp
│   └── robots.txt
├── src/
│   ├── assets/                # Ресурсы, обрабатываемые сборщиком
│   │   ├── fonts/
│   │   ├── icons/
│   │   ├── images/
│   │   └── videos/
│   ├── components/
│   │   └── ui/                # Переиспользуемые UI-компоненты
│   ├── layouts/
│   │   └── BaseLayout.astro   # HTML-каркас, SEO и глобальные подключения
│   ├── sections/              # Смысловые блоки главной страницы
│   │   ├── Hero.astro
│   │   ├── About.astro

│   │   ├── index.astro
│   │   └── 404.astro
```

Названия и состав секций могут уточняться вместе с контентом и дизайном, но их архитектурная роль остается неизменной.

### Ответственность каталогов

#### `src/pages`

Файлы маршрутов. `index.astro` собирает страницу из layout и готовых секций. В этом слое не размещаются переиспользуемые UI-компоненты и объемная бизнес-логика.

#### `src/layouts`

Общие шаблоны страниц. `BaseLayout.astro` отвечает за:

- структуру HTML-документа;
- `lang`, viewport и favicon;
- title, description, canonical и Open Graph;
- подключение глобальных стилей;
- общие аналитические скрипты.

#### `src/sections`

Крупные смысловые блоки лендинга. Секция может использовать UI-компоненты, ресурсы и локальную логику, но не должна зависеть от другой секции.

#### `src/components/ui`

Небольшие переиспользуемые элементы: кнопки, ссылки, иконки, элементы управления и другие визуальные примитивы. Компонент помещается сюда только тогда, когда имеет самостоятельный интерфейс или используется более одного раза.

#### `src/assets`

Шрифты, изображения, иконки и видео, которые импортируются из компонентов и обрабатываются Astro/Vite. Изображения, участвующие в оптимизации Astro, также хранятся здесь.

#### `public`

Файлы, которые должны сохранить исходное имя и попасть в корень `dist` без обработки: favicon, `robots.txt`, Open Graph-изображение и файлы подтверждения домена.

#### `src/styles`

- `global.css` — единая точка подключения CSS и Tailwind;
- `theme.css` — цвета, шрифты, размеры, breakpoints и другие дизайн-токены;
- `fonts.css` — объявления `@font-face`;
- `base.css` — нормализация и базовое поведение элементов;
- `typography.css` — глобальные правила типографики.

#### `src/utils`

Чистые вспомогательные функции без привязки к DOM и конкретным секциям. Каталог создается только при появлении реальной общей логики.

### Архитектурные правила

- По умолчанию используются `.astro`-компоненты без клиентской гидратации.
- JavaScript добавляется только для реальной интерактивности.
- React или другая UI-библиотека не подключается без обоснованной необходимости.
- Секции не импортируют друг друга и собираются только на уровне страницы.
- Общий UI не содержит знания о конкретных секциях и контенте спектакля.
- Дизайн-токены задаются централизованно в `theme.css`.
- Tailwind используется для композиции и основных стилей; сложные уникальные эффекты допускается инкапсулировать в scoped-стилях Astro-компонента.
- Абстракция создается после появления повторного использования, а не заранее.
- Контент и декоративные элементы отделяются от семантической структуры страницы.
- Анимации учитывают `prefers-reduced-motion`.

### Именование

- Astro-компоненты и секции: `PascalCase.astro`;
- утилиты и обычные модули: `camelCase.ts`;
- CSS-файлы и статические ресурсы: `kebab-case`;
- компоненты получают понятные предметные имена без сокращений;
- суффиксы `Component`, `Block` и `Wrapper` не используются без необходимости.

## Сборка

Перед сборкой рекомендуется выполнить проверки:

```bash
npm run check
npm run format:check
npm run build
```

Результат статической сборки появится в каталоге `dist` и может быть опубликован на любом хостинге статических сайтов.
